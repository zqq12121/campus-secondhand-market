# 上线部署

单台 Linux 云服务器 + 域名 + HTTPS，用 docker compose 跑全部服务。开发环境的用法见根目录 README。

## 1. 部署形态

```text
公网 ──► 80 / 443 ──► frontend（Nginx：静态资源 + HTTPS + 反向代理）
                          ├─ /api /ws /uploads ──► backend :8080（prod profile）
                          └─ /api/v1/ai        ──► ai :8090
           容器内网：mysql、redis（有密码）、rabbitmq（有密码）、elasticsearch（可选）
           certbot：每 12 小时检查证书，到期前 30 天自动续期
```

与开发配置（`docker-compose.yml`）相比，生产覆盖文件 `docker-compose.prod.yml` 做了这些改动：

| 项 | 生产配置 |
| --- | --- |
| 对外端口 | 只开 80 / 443；MySQL、Redis、RabbitMQ（含 15672 管理台）、ES 不映射到宿主机 |
| 密码 | Redis `requirepass`，RabbitMQ 自定义账号；未设置时 compose 直接报错 |
| 后端 | `SPRING_PROFILES_ACTIVE=prod`：启动自检（见第 4 节）、关闭 Swagger、优雅停机、隐藏错误详情 |
| 支付 | 默认 `PAY_MODE=disabled`：关闭担保交易，只允许面交，前端自动隐藏担保相关入口 |
| 运维 | 全部服务 `restart: unless-stopped`、日志按 20 MB × 5 轮转、MySQL / Redis / RabbitMQ / 后端带健康检查 |
| HTTPS | TLS 1.2/1.3、HTTP 自动跳转、HSTS、安全响应头；用户上传目录禁止被当页面执行 |

## 2. 服务器准备

- 配置：2 核 4 GB 起步（AI 助手的 embedding 模型约占 1 GB 内存；不用 AI 助手可以 2 核 2 GB）。系统 Ubuntu 22.04 / 24.04。
- 安装 Docker Engine 与 compose 插件（compose 需 v2.24 以上，覆盖文件用到 `!reset`）：

  ```bash
  curl -fsSL https://get.docker.com | sh
  ```

- 云厂商安全组只放行 22、80、443。
- 域名 A 记录解析到服务器公网 IP。国内服务器使用 80/443 需要先完成 ICP 备案。

## 3. 首次部署

1. 拉代码：

   ```bash
   sudo mkdir -p /opt/campus-trade && sudo chown $USER /opt/campus-trade
   git clone <仓库地址> /opt/campus-trade && cd /opt/campus-trade
   ```

2. **改学校数据**（只在数据库首次初始化时生效，之后要改需直接改库）：
   - `sql/init_data.sql` 里的 `school`（学校名、邮箱后缀，如 `@xxx.edu.cn`）和 `campus`（校区）。前端登录页、首页的邮箱后缀都从这里读取。
   - `ai-service/knowledge/账号与评价.md` 中的邮箱后缀说明，改成你们学校的。

3. 生成 `.env`：

   ```bash
   cp .env.example .env
   ```

   必须修改的项：

   | 变量 | 取值 |
   | --- | --- |
   | `MYSQL_PASSWORD` | 强随机密码 |
   | `REDIS_PASSWORD` | 强随机密码 |
   | `RABBITMQ_USER` / `RABBITMQ_PASSWORD` | 不要用 guest |
   | `JWT_USER_SECRET` / `JWT_ADMIN_SECRET` | 各自 `openssl rand -base64 48`，两者不同 |
   | `ADMIN_INIT_USERNAME` / `ADMIN_INIT_PASSWORD` | 首个超级管理员，密码至少 12 位；首次启动后可清空 |
   | `PAY_MODE` | `disabled`（未接支付宝正式环境时） |
   | `MAIL_ENABLED=true` 及 `MAIL_HOST` / `MAIL_USERNAME` / `MAIL_PASSWORD` / `MAIL_FROM` | SMTP 发信账号，注册和找回密码靠它 |
   | `DOMAIN` | 如 `trade.example.edu.cn` |
   | `PUBLIC_BASE_URL` | `https://<DOMAIN>` |
   | `CERT_EMAIL` | 证书到期提醒邮箱 |
   | `AI_MYSQL_PASSWORD` | ai-service 只读账号密码（首次初始化时自动建号） |
   | `DEEPSEEK_API_KEY` | AI 助手必填；留空时 ai 容器启动失败并反复重启，只有助手不可用，其余功能不受影响 |

   一次生成多个随机串：

   ```bash
   for k in MYSQL_PASSWORD REDIS_PASSWORD RABBITMQ_PASSWORD AI_MYSQL_PASSWORD; do echo "$k=$(openssl rand -hex 24)"; done
   ```

   ```bash
   chmod 600 .env
   ```

4. 签发证书（只需一次）：

   ```bash
   ./deploy/init-cert.sh
   ```

5. 启动：

   ```bash
   docker compose -f docker-compose.yml -f docker-compose.prod.yml --profile app up -d --build
   ```

   为少打字可以建个别名：

   ```bash
   echo "alias dc='docker compose -f docker-compose.yml -f docker-compose.prod.yml --profile app'" >> ~/.bashrc && source ~/.bashrc
   ```

6. 检查：

   ```bash
   docker compose -f docker-compose.yml -f docker-compose.prod.yml --profile app ps
   ```

   所有服务应为 `running`，backend 为 `healthy`。浏览器打开 `https://<DOMAIN>` 和 `https://<DOMAIN>/admin/`，用 `ADMIN_INIT_*` 登录后台，再用一个校园邮箱走一遍注册。

## 4. 后端启动自检

prod profile 下，下列配置不合格时后端拒绝启动，日志会逐条列出原因（`docker compose ... logs backend`）：

- JWT 密钥仍是示例值，或用户端与后台密钥相同
- `ADMIN_INIT_PASSWORD` 是示例值或少于 12 位
- `PAY_MODE=mock`（任何人都能把订单标为已支付）
- `PAY_MODE=alipay` 却用着沙箱网关
- `MAIL_ENABLED=false`（验证码只写日志，用户无法注册）
- `UPLOAD_PUBLIC_BASE_URL` 指向 localhost

## 5. 日常运维

以下命令都在 `/opt/campus-trade` 下执行，`dc` 为第 3 步的别名。

| 操作 | 命令 |
| --- | --- |
| 发布新版本 | `git pull && dc up -d --build` |
| 看日志 | `dc logs -f --tail=200 backend` |
| 重启单个服务 | `dc restart backend` |
| 进 MySQL | `docker exec -it campus-trade-mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" campus_trade'` |
| 已有库升级表结构 | 按版本执行 `sql/upgrade/` 下对应脚本，用法见脚本头注释 |

### 备份

```bash
./deploy/backup.sh
```

备份 MySQL 全库和上传图片到 `./backups`，默认保留 14 天。加到 crontab 每天执行：

```bash
(crontab -l 2>/dev/null; echo "0 3 * * * cd /opt/campus-trade && ./deploy/backup.sh >> backups/backup.log 2>&1") | crontab -
```

单机备份防不了整机故障，请定期把 `backups/` 同步到对象存储或另一台机器。

恢复数据库：

```bash
gunzip -c backups/mysql-<时间>.sql.gz | docker exec -i campus-trade-mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD"'
```

## 6. 以后接入支付宝担保交易

1. 在支付宝开放平台创建正式应用并签约「电脑网站支付」（需要企业或个体工商户资质）。
2. `.env` 中设置 `PAY_MODE=alipay`、`ALIPAY_APP_ID`、`ALIPAY_PRIVATE_KEY`、`ALIPAY_PUBLIC_KEY`，`ALIPAY_GATEWAY=https://openapi.alipay.com/gateway.do`。
3. 异步通知地址由 compose 自动设为 `https://<DOMAIN>/api/pay/alipay/notify`，在开放平台填写同一地址。
4. `dc up -d backend`。前端通过 `GET /api/v1/common/config` 的 `guaranteeEnabled` 自动显示担保入口。

## 7. 上线前检查清单

- [ ] `sql/init_data.sql` 已改成真实学校名、邮箱后缀和校区
- [ ] `.env` 中的密码、密钥都是新生成的随机值，文件权限 600
- [ ] SMTP 能发信：用真实校园邮箱注册收到验证码
- [ ] `https://<DOMAIN>` 证书有效，`http://` 自动跳转
- [ ] 服务器外部扫不到 3306 / 6379 / 5672 / 15672 / 9200（`nc -zv <IP> 3306` 应失败）
- [ ] 后台能登录，并已在「系统」里修改初始管理员密码、清空 `.env` 中的 `ADMIN_INIT_PASSWORD`
- [ ] 后台已配置公告、敏感词
- [ ] 备份 crontab 已添加，并实际恢复过一次
- [ ] 平台用户协议与隐私政策已准备（收集了学生邮箱、聊天记录等个人信息）
