## 1. 通用约定

### 1.1 基础路径

| 端 | 前缀 | 说明 |
| --- | --- | --- |
| 用户端 | `/api/v1` | 学生端 Web |
| 管理后台 | `/api/admin/v1` | 独立登录、独立 JWT |
| 支付回调 | `/api/pay` | 支付宝服务器调用，不走 JWT |
| WebSocket | `/ws` | STOMP over WebSocket |

### 1.2 鉴权

- 请求头：`Authorization: Bearer <token>`。
- 用户端 JWT 有效期 7 天；登出、封禁、改密码后 token 进 Redis 黑名单立即失效。
- 后台 JWT 与用户端 JWT 使用不同签名密钥（环境变量 `JWT_USER_SECRET` / `JWT_ADMIN_SECRET`），互不通用。
- 本文"鉴权"列含义：`公开` 无需登录；`登录` 需用户 token；`登录?` 可选（带 token 时返回个性化字段，如 `favorited`）；后台接口写明所需**权限码**。

### 1.3 统一响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "traceId": "7f3c1a9e2b"
}
```

| HTTP 状态 | 场景 |
| --- | --- |
| 200 | 成功，或业务错误（`code ≠ 0`，见附录 B） |
| 401 | 未登录、token 过期、token 在黑名单 |
| 403 | 已登录但无权限（后台权限码不足、账号封禁） |
| 429 | 触发限流 |
| 500 | 服务端异常 |

### 1.4 分页

请求：`page`（从 1 开始，默认 1）、`size`（默认 20，最大 50）。

```json
{
  "list": [],
  "total": 128,
  "page": 1,
  "size": 20
}
```

聊天历史例外，使用游标分页（见 7.4）。

### 1.5 数据格式

| 类型 | 约定 | 示例 |
| --- | --- | --- |
| ID | 统一序列化为**字符串**（BIGINT 超出 JS 安全整数） | `"1024"` |
| 金额 | 字符串，2 位小数，单位元 | `"12.50"` |
| 时间 | `yyyy-MM-dd HH:mm:ss`，东八区 | `"2026-11-19 21:30:00"` |
| 枚举 | 传数据库数值（与 schema 注释一致），附录 A 列全 | `"status": 2` |
| 字段命名 | camelCase | `campusId` |
| 敏感字段 | 邮箱除本人外一律脱敏 `zh***@wu.edu.cn`；他人主页不返回邮箱 | |

### 1.6 限流（Redis 滑动窗口，用户 + IP）

| 接口 | 默认阈值（配置项） |
| --- | --- |
| 发送邮箱验证码 | 同邮箱 60s/1 次；同 IP 1h/20 次 |
| 登录 | 同账号 15 分钟失败 5 次锁 15 分钟 |
| 发布商品 | 每天 20 件（信用 40–59 为 3 件） |
| 下单 | 1 分钟 10 次；24h 内取消未支付订单 ≥5 次当日禁止下单 |
| 发消息 | 1 秒 5 条 |

超限返回 HTTP 429 + `code=429`，`data.retryAfter` 为秒数。

## 3. 账号与认证

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| POST | `/auth/email-codes` | 公开 | 发送邮箱验证码 |
| POST | `/auth/register` | 公开 | 校园邮箱注册（即完成学生认证） |
| POST | `/auth/login` | 公开 | 登录 |
| POST | `/auth/logout` | 登录 | 登出，token 进黑名单 |
| POST | `/auth/password/reset` | 公开 | 验证码找回密码 |

### 3.1 POST `/auth/email-codes`

```json
{ "email": "zhangsan@wu.edu.cn", "scene": "REGISTER" }
```

| 字段 | 说明 |
| --- | --- |
| email | 后缀必须等于 `school.email_suffix`（`@wu.edu.cn`） |
| scene | `REGISTER`（邮箱须未注册）/ `RESET_PASSWORD`（邮箱须已注册） |

规则：6 位数字，Redis 存 5 分钟，同邮箱 60 秒内只能发一次。成功返回 `data: null`。

错误：`1001` 邮箱后缀不合法、`1002` 邮箱已注册、`1008` 邮箱未注册、`1004` 发送过于频繁。

### 3.2 POST `/auth/register`

```json
{
  "email": "zhangsan@wu.edu.cn",
  "code": "385920",
  "password": "abc12345",
  "nickname": "张三",
  "campusId": "1"
}
```

| 字段 | 校验 |
| --- | --- |
| password | 8–20 位，必须同时含字母和数字 |
| nickname | 2–16 字 |
| campusId | 必须属于该学校 |

成功后：用户初始信用分 80（初始分不写 `credit_log`），直接返回登录态，结构同 3.3。

错误：`1001`、`1002`、`1003` 验证码错误或过期、`1007` 密码格式不符。

### 3.3 POST `/auth/login`

```json
{ "email": "zhangsan@wu.edu.cn", "password": "abc12345" }
```

```json
{
  "token": "eyJhbGciOi...",
  "expiresIn": 604800,
  "user": {
    "id": "1024",
    "nickname": "张三",
    "avatarUrl": null,
    "campusId": "1",
    "creditScore": 80,
    "creditLevel": "GOOD",
    "status": 0
  }
}
```

错误：`1005` 邮箱或密码错误（`data.remainingAttempts` 剩余次数）、`1006` 账号已锁定（`data.retryAfter` 秒）、`1009` 账号已封禁（`data.banUntil`，永久为 null）。

### 3.4 POST `/auth/logout`

无请求体。将当前 token 的 jti 写入 Redis 黑名单，TTL = token 剩余有效期。

### 3.5 POST `/auth/password/reset`

```json
{ "email": "zhangsan@wu.edu.cn", "code": "385920", "newPassword": "xyz98765" }
```

成功后该用户所有已签发 token 失效（Redis 记录 `pwdChangedAt`，鉴权时比较 `iat`）。

### 4.7 POST / DELETE `/users/{id}/block`

不能拉黑自己（`400`）。重复拉黑幂等返回成功。拉黑后对方不能向我发消息、不能下单我的商品。

### 4.8 GET `/users/{id}` 他人主页

```json
{
  "id": "2048",
  "nickname": "李四",
  "avatarUrl": "...",
  "college": "外国语学院",
  "campusName": "廷根",
  "bio": "...",
  "creditScore": 92,
  "creditLevel": "EXCELLENT",
  "badge": true,
  "goodRate": "98.0",
  "reviewCount": 50,
  "onSaleCount": 7,
  "soldCount": 41,
  "blocked": false,
  "joinedAt": "2025-09-01"

```

- 不返回邮箱、余额。`badge` = 信用 ≥ 90。

- 账号已注销/封禁：仍可查看，`status` 字段返回 2，前端置灰。

### 4.9 GET `/users/{id}/goods`

参数：`page`、`size`。只返回 `status=2 在售`。列表项同 5.1。

### 5.3 GET `/goods/{id}` 详情

```json
{
  "id": "5001",
  "title": "高等数学 同济第七版 上下册",
  "description": "有少量笔记……",
  "images": ["...cover.jpg", "...2.jpg"],
  "categoryId": "101",
  "categoryPath": ["教材书籍", "专业教材"],
  "price": "25.00",
  "originalPrice": "68.00",
  "conditionLevel": 3,
  "tradeMode": 3,
  "campusId": "1",
  "campusName": "贝克兰德",
  "location": "南区 3 栋楼下",
  "stock": 1,
  "status": 2,
  "auditRemark": null,
  "viewCount": 120,
  "favoriteCount": 4,
  "publishedAt": "2026-11-18 20:11:00",
  "seller": {
    "id": "2048",
    "nickname": "李四",
    "avatarUrl": "...",
    "creditScore": 92,
    "creditLevel": "EXCELLENT",
    "badge": true,
    "goodRate": "98.0",
    "onSaleCount": 7
  },
  "favorited": false,
  "isMine": false,
  "canBuy": true,
  "cannotBuyReason": null
}
```

- 可见性：在售（2）、交易中（4）、已售出（5）对所有人可见；其他状态仅卖家本人可见，他人访问返回 `2001 商品不存在`。
- `viewCount` 每次访问 Redis +1，定时回写；同一用户 30 分钟内重复访问不计。
- `canBuy=false` 时 `cannotBuyReason` 取值：`SELF` 自己的商品 / `NOT_ON_SALE` / `OUT_OF_STOCK` / `BLOCKED` 被卖家拉黑 / `NOT_LOGIN`。
- 详情做 Redis 缓存（空值缓存防穿透、互斥锁防击穿），个性化字段（`favorited/isMine/canBuy`）不进缓存。

### 5.4 POST `/goods` 发布 / 存草稿

```json
{
  "title": "高等数学 同济第七版 上下册",
  "description": "有少量笔记……",
  "images": ["...cover.jpg", "...2.jpg"],
  "categoryId": "101",
  "price": "25.00",
  "originalPrice": "68.00",
  "conditionLevel": 3,
  "tradeMode": 3,
  "campusId": "1",
  "location": "南区 3 栋楼下",
  "stock": 1,
  "draft": false
}
```

| 字段 | 必填 | 校验 |
| --- | --- | --- |
| title | 是 | ≤ 30 字 |
| description | 是 | ≤ 1000 字 |
| images | 是 | 1–9 张，首张为封面，必须是本平台上传返回的 URL |
| categoryId | 是 | 必须是启用中的**二级**分类 |
| price | 是 | `0` 或 `0.01–99999`，两位小数 |
| originalPrice | 否 | ≥ price |
| conditionLevel | 是 | 1–4 |
| tradeMode | 是 | 1/2/3；`price=0` 时必须为 1；卖家信用 < 60 时不能含担保（2/3） |
| campusId | 否 | 默认取用户所属校区 |
| location | 否 | ≤ 64 字 |
| stock | 否 | 默认 1，1–99 |
| draft | 否 | `true` 只存草稿（status=0），不校验必填项以外的业务限额 |

`draft=false` 时的处理流程：

1. 校验：用户状态（禁言/封禁不可发布）、信用分 ≥ 40、在售 ≤ 50 件、当日发布 ≤ 20 件（信用 40–59 为 3 件）。
2. 敏感词检测（DFA，标题 + 描述）→ 写 `audit_record`（`auditor_type=1`）。
3. 未命中且信用分 ≥ 80 → `status=2 在售`，写 `published_at`；否则 → `status=1 待审核`。
4. 上架时触发求购匹配（P1，异步）。

```json
{ "id": "5001", "status": 2, "hitWords": [] }
```

错误：`2001`–`2008`（见附录 B）。

### 5.5 PUT `/goods/{id}` 编辑

请求体同 5.4（`draft` 仅对草稿有效）。规则：

| 当前状态 | 允许编辑 | 结果 |
| --- | --- | --- |
| 0 草稿 / 3 审核驳回 / 6 已下架 | 是 | `draft=true` 保持草稿；否则按 5.4 流程重新审核 |
| 2 在售 | 是 | 只改了 price/originalPrice/stock/location → 不重审；改了标题/描述/图片/分类 → 重新走 5.4 步骤 2–3 |
| 1 待审核 | 是 | 重新走审核 |
| 4 交易中 / 5 已售出 / 7 强制下架 | 否 | `2003 当前状态不可编辑` |

返回：`{ "id": "5001", "status": 1, "hitWords": ["代考"] }`。

### 5.6 POST `/goods/{id}/off-shelf`

仅卖家本人；`2 在售` 或 `1 待审核` → `6 已下架`。交易中不可下架（`2003`）。

### 5.7 POST `/goods/{id}/on-shelf`

`6 已下架`（含 60 天自动下架）→ 按 5.4 步骤 1–3 重新上架，刷新 `published_at`。`7 强制下架` 不可重新上架。返回同 5.4。

### 5.8 DELETE `/goods/{id}`

仅 `0/3/6` 状态可删，逻辑删除。已售出商品保留不可删（订单快照依赖）。

### 5.9 GET `/users/me/goods`

参数：`status`（选填，单值）、`page`、`size`。列表项在 5.1 基础上加 `status, auditRemark, viewCount, stock, updatedAt`；`status=0` 即草稿箱。

```json

  "list": [], "total": 6, "page": 1, "size": 20,
  "counts": { "0": 1, "1": 0, "2": 5, "3": 0, "4": 1, "5": 12, "6": 2, "7": 0 }
}
```

### 5.10 POST / DELETE `/goods/{id}/favorite`

幂等。同步维护 `goods.favorite_count`。不能收藏自己的商品（`2009`）。返回 `{ "favorited": true, "favoriteCount": 5 }`。

### 5.11 GET `/users/me/favorites`

参数：`page`、`size`。列表项同 5.1 并加 `status`（已下架/已售出的收藏仍显示，前端置灰）、`favoritedAt`。

### 8.1 POST `/orders` 下单

```json
{
  "goodsId": "5001",
  "quantity": 1,
  "tradeMode": 2,
  "requestId": "b0c1e2f3-..."
}
```

| 字段 | 校验 |
| --- | --- |
| tradeMode | 1 面交 / 2 担保；必须被商品 `trade_mode` 支持；卖家信用 < 60 时不可选 2 |
| quantity | 1 ≤ quantity ≤ 当前库存 |

```json
}
```

前端把 `payForm` 写入新窗口执行即跳转支付宝沙箱收银台。`return_url` 指向前端 `/order/{id}?from=alipay`，该页调 8.8 轮询结果（**不能**以跳转回来作为支付成功依据）。

错误：`5101` 订单已超时关闭、`5102` 订单状态不允许支付。

### 8.8 GET `/orders/{id}/pay-status`

```json
{ "orderStatus": 40, "paymentStatus": 1, "paidAt": "2026-11-19 21:03:00" }
```

若本地仍为待支付，后端主动调 `alipay.trade.query` 补偿一次。

### 8.9 POST `/api/pay/alipay/notify` 支付宝异步通知

- 不走 JWT；`Content-Type: application/x-www-form-urlencoded`，参数为支付宝标准通知字段。
- 处理：① 用支付宝公钥（环境变量 `ALIPAY_PUBLIC_KEY`）验签；② 校验 `app_id`、`out_trade_no` 存在、`total_amount` 一致；③ `trade_status ∈ {TRADE_SUCCESS, TRADE_FINISHED}` 时，`payment` 以 `out_trade_no` 唯一键 + 状态条件更新实现幂等，订单 `30 → 40`（乐观锁）；④ 存 `notify_payload`。
- 订单已被超时取消后才收到成功通知：自动发起全额退款，写 `order_log` 备注。
- 响应体：处理成功或已处理过返回纯文本 `success`，否则返回 `failure`（支付宝会重试）。

### 8.10 POST `/orders/{id}/deliver`

担保 `40 → 50`，卖家点"已交货"。写 `delivered_at`，投递 7 天延时消息（自动确认收货）。

### 8.11 POST `/orders/{id}/confirm-receipt`

担保 `50 → 70`，买家确认收货。在同一事务中：卖家 `balance += total_amount`、写 `balance_log`（`order_id + type` 唯一，保证只放款一次）。其余同 8.5。

### 9.3 POST `/after-sales/{id}/agree`

卖家同意（`status 0 → 1`）。调支付宝 `alipay.trade.refund`（`out_refund_no` 唯一保证退款幂等）→ 成功后：售后写 `refunded_at/closed_at`，`payment.status=3`，订单 `60 → 90`，回补库存，商品恢复在售。

退款调用失败：售后保持 `1 卖家同意`，订单保持 60，定时任务按 `out_refund_no` 重试。

### 9.4 POST `/after-sales/{id}/reject`

```json
{ "reply": "发货前测试正常，有视频" }
```

`reply` 必填 ≤ 200 字，`status 0 → 2`。

- type=1：售后关闭，订单 `60 → 40`，卖家继续交货。
- type=2：订单保持 60，买家可 `appeal` 或 `withdraw`，时限 48 小时（售后详情 `appealDeadline`）。超时未处理：售后关闭（`status` 保持 2，写 `closed_at`），订单 `60 → 70` 自动确认收货并放款给卖家（`AUTO_CONFIRM_AFTER_REJECT`）。

### 9.5 POST `/after-sales/{id}/appeal`

```json
{ "remark": "补充说明，选填，≤200 字" }
```

`remark` 写入 `order_log.remark`（`after_sale` 表无买家补充说明字段，见附录 D）。

### 9.6 POST `/after-sales/{id}/withdraw`

`status ∈ {0, 2}` 且未关闭时买家可撤销 → `6`。订单回到申请前状态（40 或 50），重新投递剩余时长的自动确认消息。

### C.2 流转图

```text
面交：  CREATE → [10 待卖家确认] —SELLER_CONFIRM→ [20 待面交] —COMPLETE / AUTO_COMPLETE→ [70 已完成]
                       │                               │
                       └—CANCEL / AUTO_CANCEL_UNCONFIRMED┴—CANCEL→ [80 已取消]

担保：  CREATE → [30 待支付] —PAY→ [40 待交货] —DELIVER→ [50 待收货] —CONFIRM_RECEIPT / AUTO_CONFIRM→ [70 已完成]
                    │                 │                      │
          CANCEL / AUTO_CANCEL_UNPAID  APPLY_CANCEL           APPLY_REFUND
                    ↓                 ↓                      ↓
              [80 已取消]        [60 售后中] ←———————————————┘
                                      ├—AGREE_AFTER_SALE / ARBITRATE_REFUND→ [90 已退款]
                                      ├—ARBITRATE_RELEASE / AUTO_CONFIRM_AFTER_REJECT→ [70 已完成]
                                      └—REJECT(type=1) / WITHDRAW→ 回到 40 或 50
```

### C.3 实现约束

- 状态机校验 `(当前状态, 动作, 操作人角色)`，不合法返回 `5007`；乐观锁失败返回 `409`。
- 每次流转：写 `order_log` → 给对方发通知 + 在双方会话插入系统消息（`type=4`）。
- 延时消息消费时再次校验状态与版本号，状态已变则丢弃；定时任务按 `idx_status_time` 兜底扫描超时订单。
- 进入 80/90 回补库存，商品 `4 → 2`（商品已被下架/强制下架则不恢复）。

## 附录 D：设计中发现的问题与假设

以下是对照 PRD 与 schema 时发现的缺口，按"不改表"的方式处理，已于 2026-11-19 确认照此执行。

| # | 问题 | 本文处理方式 |
| --- | --- | --- |
| 1 | PRD 通知类型含"认证结果"，但注册即认证、`notification.type` 也无此值 | 不发认证通知，`verified` 恒为 true |
| 2 | 买家申请平台介入时无处存放补充说明（`after_sale` 无对应字段） | 存 `order_log.remark`；若要在后台单独展示，建议 `after_sale` 加 `appeal_remark VARCHAR(500)` |
| 3 | PRD 只写"支付后、交货前买家申请取消，卖家同意即退款"，没说卖家能否拒绝 | 允许拒绝，拒绝后订单回到 40 继续交货，不能申请介入 |
| 4 | PRD 未定义"禁言"具体限制 | 禁言 = 不能发消息、发布商品与求购；可浏览、购买 |
| 5 | 面交"卖家确认后主动取消 −3"，未提买家在 20 状态取消 | 买家在 20 状态取消同样 −3（爽约同等处理） |
| 6 | 商品卡片消息 `content` 只存商品 ID，商品后续改价会导致聊天记录展示变化 | 展示实时商品信息并标注当前状态，不做快照 |
| 7 | 多数量商品（stock > 1）下单后商品状态 | 库存未归 0 时保持"在售"，归 0 才变"交易中" |
| 8 | 求购"我有"响应无关联表，无法统计某求购收到几次响应 | 本期不统计；如需要建议加 `want_response` 表 |
| 9 | 订单下单页无备注字段（schema 无） | 不提供备注，买卖双方通过聊天约定 |
| 10 | 退款只支持全额 | `refund_amount` 固定为订单金额，接口不接收金额参数 |
| 11 | 收货前退款被卖家拒绝后，买家既不申请介入也不撤销，PRD 未定义如何收尾 | 2026-11-20 确认：48 小时后自动确认收货并放款。截止时间 = 拒绝时间（`after_sale.updated_at`，拒绝后该行不再更新）+ 48h，不加字段 |
